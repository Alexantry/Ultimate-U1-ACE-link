Prepare the U1 firmware

简体中文 · Guided installation · Manual source installation

The wizard downloads the exact U1 extended firmware (the original upstream file), verifies it, and copies it to a USB drive. You then update on the U1 screen and enable Advanced Mode and Root Access.

This stage does not flash the ACE. The ACE firmware stage follows in the same wizard.

IMPORTANT

You must confirm the first firmware update on the U1 screen.

You must also enable Advanced Mode and Root Access before remote installation.

What you need

  • A Windows 10 or Windows 11 computer with internet access, and the extracted project package.
  • A removable USB drive that already uses FAT32, with at least 300 MB free. The wizard does not format disks.
  • An idle, cold U1: printing and all filament operations finished, heating and ACE drying off, nozzles and bed below 50 °C.
  • For a first installation: unload all four heads with the normal printer controls, remove the filament from all four ACE inlets, then let the heaters cool again. An update of this project does not require empty inlets.
  • Your own copy of any custom configuration, made before the firmware update. The project's later backup does not protect it.

If the U1 already runs the exact supported firmware, select menu 1. U1 is ready instead. Do not replace a customized or newer firmware merely to pass an installation check.

Guided steps

  1. Extract the complete project ZIP. Double-click START-HERE.cmd, select your language, then select 2. Prepare U1 firmware USB.
  2. Insert the FAT32 USB drive into the computer. Select it from the list, check its letter, label, and capacity, then confirm.
  3. Wait for download, SHA-256 verification, file copy, and destination verification. Then use Windows Eject.
  4. Insert the drive into the U1. Select Settings → About → Firmware Version → Local Update on the U1 screen.
  5. Select U1_extended_2.0.0-paxx12-24_upgrade.bin. Confirm the update. Wait for the update and restart to finish. Keep power connected.
  6. Open Settings → Maintenance → Advanced Mode. Enable it and complete the requested restart.
  7. Open Settings → Maintenance → Root Access. Read the notice, scroll to Agree, and select Open.
  8. Check Wi-Fi. Reconnect if necessary. Read the current printer IP address.
  9. Continue in the same computer wizard. It asks for the printer address and SSH password.

The wizard does not overwrite a file that has the same name but different content. Inspect that file yourself before another attempt. If no suitable drive appears, use a FAT32 removable drive. Do not change the program to force another disk.

If the U1 update fails, keep the displayed error text and use Snapmaker's firmware-update recovery instructions. Do not try random firmware files. Host integration rollback does not reverse a U1 firmware update.

Tube lengths and take-up settings

Settings and calibration

中文说明 · Guided installation

Three distances control loading and unloading. All four slots share them and the speed settings, so check all four tube paths.

Distances are in millimeters (mm). Speeds are requested values in mm/s, not measured filament speeds.

LetterJSON settingFunctionReference only
Aretract_lengthMain ACE return distance, after the U1 releases filament from the hotend.1250 mm at speed 80
Bfast_load_lengthFast segment of a load. It must end before the head, leaving a slow approach.1150 mm at speed 200
Cforward_takeup_lengthForward movement after A, to draw loose filament into the PTFE tube.Start at 0; tested reference 300 mm at speed 50
CAUTION

1250, 1150, and 300 are reference values for one tested arrangement. They are not universal values.

Do not copy a measured tube length directly into A, B, or C.

Loading stops at the U1 head sensor. It does not intentionally push until a mechanical stall.

A travel limit and a timeout stop an unsuccessful attempt.

  • config/settings.tested-reference.json has C = 300 and requests replacement of existing settings. Do not use it to overwrite your own settings.

The installer rejects values outside these limits. Passing the check does not prove that the values suit your tubes.

  • C is 0–500 mm, and is smaller than both A and B.
  • B does not exceed A, and is smaller than the 2500 mm load limit.
  • Fast speed does not exceed 200. Slow and take-up speeds do not exceed 50.

How the distances interact

Inserting filament starts only the ACE's short bite and NFC reading. Long transport starts when you select Load on the U1.

With a valid starting-position record, the controller uses:


fast request = max(0, B - recorded forward advance)
slow allowance = 2500 - fast request
  • The head sensor can stop either stage early. The slow stage runs at speed 50, and its allowance is a maximum, not a target.
  • After a successful unload with B = 1150 and C = 300, the fast request is 850 mm. The controller subtracts the recorded C itself. Do not enter 850 as B to compensate for C = 300. That would produce a 550 mm fast request.
  • After a restart, an interrupted operation, or an uncertain position, there is no fast stage. A slow first load is then normal.

Unload: the U1 releases the hotend, the ACE retracts A at speed 80, then feeds C at speed 50 if enabled, and records C for the next load.

Afterwards, filament must remain in the ACE inlet and rear PTFE tube, and the U1 head sensor must be empty.

Calibrate the PTFE paths

Measure the four paths

  1. Finish printing and all filament operations. Let the printer cool. Remove power before disconnecting tubing or hardware.
  2. Label both ends of each tube with its ACE slot and U1 head.
  3. Measure each installed tube along its bends, not the straight distance. Record sections you cannot reach as unknown, not as zero.
  4. Choose the parking point for the tip after unloading: inside the ACE-side PTFE tube. The tip must not reach the head or leave the ACE inlet.
  5. Reconnect every tube securely before a powered test.
  • A tape measure does not cover the ACE internal path, the initial bite, the head path, or the hotend release. Measurements help assess clearance only.
  • Check B against the shortest path to a head. The reference A and B differ by 100 mm. That does not establish a 100 mm clearance on your printer.
  • If the four paths have no safe common setting, correct the tube arrangement first.

Choose and test A and B

  1. Start from recorded, working values for your arrangement, when available. Resolve unknown dimensions before entering a long return. You can exit the wizard without installing.
  2. Set C to 0. Keep fast speed 200, approach speed 50, and return speed 80.
  3. Choose B short enough to leave a slow approach before the head. Choose A to return the tip to the parking point.
  4. Enter A and B in the launcher (first installation) or with Apply changed settings.
  5. On one slot, select Load, Unload, then Load on the U1. Wait for each action to finish before the next.
  6. After motion stops, check the tip position, the head sensor, the ACE inlet, and loose filament. Keep hands away from moving rollers. Remove power before disconnecting a tube.
  7. Repeat on the other three slots with the same settings, before normal printing. Record the results in the acceptance checklist.

Adjust

  • Fast travel reaches the head: reduce B. A sensor stop does not prove sufficient clearance.
  • After unloading, the tip is too far toward the U1, the head is empty, and no fault occurred: increase A slightly, within the ACE-side margin. Retest with C = 0.
  • The tip leaves the ACE inlet: correct the physical state, then reduce A. Do not repeat Unload to recover it.
  • Unload fails, the head still detects filament, or filament slips or jams: stop. Inspect the hotend release and the tube path. Do not increase A blindly.
  • Change one distance at a time, within the clearance you can verify. After changing or rerouting any tube, set C to 0 and repeat this section. Do not use old values to find out whether a new tube is too short.
  • For other symptoms, see Troubleshooting.

Enable forward take-up

C feeds a set length toward the U1 after A. It has no tension sensor.

Enable C only after Load, Unload, and Load pass on all four slots with C = 0.

  1. Inspect the loose filament after unloading.
  2. Choose a limited C for the observed slack and the available head clearance. The tested C = 300 (slot-4 record) is not a recommendation for your setup.
  3. Keep forward_takeup_speed at or below 50.
  4. Apply the change and test one normal unload. The head must remain empty and the ACE inlet occupied.
  5. Load again without removing the filament.
  6. Repeat the checks on all four slots.
  • More C moves the parked tip closer to the head. If filament becomes tight, snags, or reaches the head, stop and reduce or disable C.
  • If slack remains, first confirm that filament moves freely. Do not increase A to compensate for excessive C.

How recognition works

  1. Spool NFC tag
  2. ACE reads and decodes
  3. U1 queries and converts
  4. Material data is displayed and kept

OpenCubic provides multi-brand decoding. U1 internal OpenRFID is a separate reader path.

  1. The ACE reader reads the tag. ACE firmware decodes it.
  2. The integration on the U1 queries the ACE and receives the decoded brand, type, and color for that slot.
  3. The integration converts names and color formats and writes the result to the U1. For example, Bambu Lab / PLA Matte becomes Bambu / PLA / Matte. An empty brand becomes Generic.

The U1 internal reader is a separate reader and is not used. The installer sets External and stops the U1 OpenRFID service.

Check External mode

  1. Open the printer's /firmware-config/ page.
  2. Find Snapmaker Components.
  3. Check Filament Detection. The selected value must be External. The retained v0.1.0 package does not set it; select External manually there.
CAUTION

Keep External selected while using this ACE integration.

Do not enable internal OpenRFID to improve ACE recognition.

That change activates a separate reader path and can conflict with ACE material handling.

Check recognition

  1. Insert filament into an empty ACE inlet. Keep your hands away from the rollers.
  2. Wait for the short bite and NFC recognition to finish.
  3. Open that slot's material details on the U1 and compare them with the spool.
  • The filament waits at the ACE. Insertion does not load it to the print head.
  • Recognition can take longer when several slots change close together. Do not issue repeated Load commands during recognition.
  • Loading and unloading keep the material data while the ACE inlet remains occupied.
  • A confirmed empty inlet clears that slot's data. An unknown or disconnected state does not.

Daily use and remote controls

Daily loading and unloading

简体中文 · Tube calibration · NFC

What to do and what happens

You do thisThis happens
Insert filament into an empty ACE inlet, hands away from the rollersThe ACE grips the filament, reads the NFC tag, and waits. It does not load to the head.
Check the material details on the U1Enter them manually if the spool has no readable tag.
Select the tool on the U1 and start normal LoadThe ACE feeds fast, then slowly until the head sensor detects filament. The U1 completes the hotend load.
Start normal Unload for the toolThe U1 releases the filament from the hotend. The ACE retracts it and keeps the tip in the ACE and its rear tube.
Select Load again without removing the filamentThe load starts directly. Material data stays while the ACE inlet remains occupied.
  • Wait for each operation to finish before sending another command.
  • After a restart or with an uncertain position, the whole feed can run at the slower speed.
IMPORTANT

Forward take-up starts disabled on new installations. Calibrate it before use.

It feeds filament toward U1 to remove loose loops. It has no tension sensor and does not drive the roller independently.

The tested example uses 1250 mm retraction at 80 mm/s, then 300 mm forward at 50 mm/s.

These are not universal distances. See the calibration procedure.

Remote operation

Screen mirror. Enable Firmware Config → Web → Remote Screen Access, then open /screen/ on that printer and use Load or Unload as on the physical screen.

The installer does not enable it. See the v24 remote-screen instructions.

Web console. For slot 1, send one of these commands and follow the printer prompts. For slots 2, 3, and 4, use EXTRUDER=1, 2, and 3.

Load:


AUTO_FEEDING EXTRUDER=0 LOAD=1

Unload:


AUTO_FEEDING EXTRUDER=0 UNLOAD=1
  • Do not send Load and Unload together.
  • Do not use ACE_FEED or ACE_RETRACT instead. They only move filament and skip the hotend workflow.
  • The optional AFC panel needs its own AFC Stub setting. This installation does not provide it by default.
Interrupted operations and recovery

Update, interrupted connections, and rollback

简体中文 · Manual installation · Troubleshooting

Run these commands in Windows PowerShell. The earlier window does not need to be open.

  • ACE firmware maintenance and U1 host integration installation are separate transactions.
  • A host backup cannot roll back ACE or U1 firmware.
  • To remove this project, or to return the ACE or the U1 to vendor firmware, see remove and restore.
  • Unknown result: keep the devices idle. Do not print. Do not resend an install or flash command.

1. Open a new window and connect

  1. Open Start, search for Windows PowerShell, and open it.
  2. Get the current U1 screen address and the recorded RemoteDir. Installation paths contain stage; manual parameter-change paths contain tuning. The wizard shows the directory on failure; its private computer log records Remote stage.
  3. Paste the block below. Enter the address and SSH password, then the exact recorded directory.
  4. For the first-contact identity check and hidden password input, see confirm the connection.

Do not guess a directory. No record: keep the error window, screen information, and files. Do not run a write from a directory that only looks recent.


$ErrorActionPreference = 'Stop'
Get-Command ssh.exe, scp.exe -CommandType Application | Out-Host
$PrinterAddress = (Read-Host 'Enter the IPv4 address shown on the U1 Wi-Fi screen').Trim()
if ($PrinterAddress -notmatch '^(?:[0-9]{1,3}\.){3}[0-9]{1,3}$' -or
    @($PrinterAddress.Split('.') | Where-Object { [int]$_ -gt 255 }).Count -gt 0) {
    throw 'STOP: Invalid IPv4 address'
}
$PrinterTarget = 'root@' + $PrinterAddress
ssh.exe $PrinterTarget 'id'
if ($LASTEXITCODE -ne 0) { throw 'STOP: SSH connection failed' }
$RemoteDir = (Read-Host 'Paste the RemoteDir path saved from the previous operation').Trim()
if ($RemoteDir -notmatch '^/userdata/ultimate-u1-ace-(?:stage|tuning)-[0-9]{8}-[0-9]{6}(?:-[a-f0-9]{8})?$') {
    throw 'STOP: Use the exact recorded staging directory'
}
ssh.exe $PrinterTarget "ls '$RemoteDir/installer.py' '$RemoteDir/manifest.json' '$RemoteDir/tools/ace_usb/wizard_backend.py'"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Recorded package files are unavailable' }

Expected: uid=0(root) and all three file paths.

Directory or files missing: do not combine files from another release. Establish the original transaction result before you transfer a replacement package or start any write.

Read ACE state before host status

This query does not open serial, restore services, or start a flash:


ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 tools/ace_usb/wizard_backend.py result --wait-seconds 30"
if ($LASTEXITCODE -ne 0) { throw 'STOP: ACE result query failed' }
ACE resultAction
PREPARING, STARTING, RUNNING, RECOVERINGKeep power connected. Repeat the same result query later.
NEEDS_ATTENTION, ERROR, or a failed queryGo to ACE interruption. Do not restart or roll back merely because Klipper is unavailable.
NONENo ACE transaction exists.

Safe terminal states also need ready: true and service_restored: true.

Only when no ACE transaction is unresolved, read host status:


ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 installer.py status"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Host status is unavailable; do not start a write' }
  • Expect klipper_state: ready. After installation, managed is true.
  • ace_version is this project's module version, not the ACE firmware version.
  • status reads the current state. It does not prove that a disconnected installer has finished or that the earlier installation succeeded.
  • If the original process can still be active, wait and keep its record. Do not roll back or install again.

2. Interrupted ACE firmware operation

Simplest path: extract the same package version, run START-HERE.cmd, and select menu 4: ACE firmware.

It reads the saved transaction first. It does not flash again automatically.

It can offer check-and-restore only for a failure before any write.

ResultAction
Operation activeKeep ACE, U1, and USB powered and connected. Keep querying.
SUCCEEDED with restored serviceReview material changes. ACE maintenance is complete; check host installation separately.
FAILED_SAFEFix the network, idle, or cooling condition. Prepare again with the same package version.
NEEDS_ATTENTION, flash_attempted: falseMenu 4 can offer probe-only restoration. Confirm once and wait.
NEEDS_ATTENTION, flash_attempted: trueDo not reflash, attempt automatic stock rollback, or force Klipper to start. Keep records and stop normal use.
Unsupported version or corrupt recordStop. Do not edit JSON, remove transactions, or change reported versions.

Without the wizard, keep using the read-only result query in section 1.

Probe-only recovery requires NEEDS_ATTENTION, flash_attempted: false, and a stopped worker. Confirm all three first.

This block restores maintenance that has not started writing. It does not update firmware:


$Raw = & ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 tools/ace_usb/wizard_backend.py result"
if ($LASTEXITCODE -ne 0) { throw 'STOP: ACE query failed' }
$SavedAce = ($Raw -join "`n") | ConvertFrom-Json
if ($SavedAce.state -ne 'NEEDS_ATTENTION' -or $SavedAce.flash_attempted -ne $false -or
    $SavedAce.operation -notmatch '^[a-f0-9]{32}$') { throw 'STOP: Probe-only recovery is not available' }
$OperationId = $SavedAce.operation
ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 tools/ace_usb/wizard_backend.py recover --operation $OperationId"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Do not repeat recovery; query its result' }
ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 tools/ace_usb/wizard_backend.py result --operation $OperationId --wait-seconds 30"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Read the saved result later; do not repeat recovery' }

Expected final result: CANCELLED_SAFE, ready: true, and service_restored: true.

  • RECOVERING: repeat only the result query in section 1. Do not repeat recover.
  • The backend refuses recovery after a flash attempt. Do not change its record.
  • Other faults can need manual maintenance; ordinary installation steps cannot guarantee recovery. See advanced ACE maintenance.

3. Interrupted host installation

Read the last result in the original window or private log:

ResultMeaning and action
installed: true, ready_samples: 3The installer reported success. Check current status and physical functions.
Automatic rollback VERIFIEDInstallation failed, but restoration was verified. Fix the original failure before you try again.
automatic rollback FAILEDRestoration is incomplete. Keep idle. Save the Backup ID and error.
SSH disconnect without a final resultSuccess or failure is unknown. Do not resend. Read status and establish the original process result.

ACE SUCCEEDED is not host installation success. Do not roll back while the original installation is still running.

4. Update this project

  1. Finish printing and filament operations. Stop drying, set every heater target to zero, and cool below 50 °C.
  2. If feed assist is still active, unload that channel normally. Wait for completion and cool again. You need not empty every slot.
  3. Save private configuration and backups. Download the complete new archive and extract it into a new folder.
  4. Wizard: select menu 1 in the new package. It keeps current parameters by default.
  5. Manual: start at step 2 of manual installation in a new window and directory. Check the plan, then install once.
  6. Do not copy a whole old JSON file into the new template. Do not set apply_existing_settings to true merely to update. To change parameters on purpose, see configuration.

Unknown edits to core files are refused, not merged. Keep those edits; do not overwrite them to bypass the check.

5. Save private backups

Managed backups are under /userdata/ultimate-u1-ace-link/backups/.

After section 1 connects, copy them into a new unique folder under Documents:


$BackupDir = Join-Path ([Environment]::GetFolderPath('MyDocuments')) ('Ultimate-U1-ACE-private-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [guid]::NewGuid().ToString('N').Substring(0,8))
New-Item -ItemType Directory -Path $BackupDir | Out-Null
scp.exe -O -r "${PrinterTarget}:/userdata/ultimate-u1-ace-link/backups" "$BackupDir"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Backup copy failed' }
Write-Host $BackupDir

Keep the displayed path. Backups can contain private configuration; do not publish them.

This is a host-file backup, not an ACE firmware, U1 firmware, or complete device image.

6. Roll back the latest host installation

Use only when the original installer has finished, no ACE transaction is unresolved, and the machine is idle and cold.

Normal rollback also requires ACE ready, drying off, and feed assist off. Do not skip these conditions.

Connect and query with section 1. Confirm that the latest backup is the intended target, then run once:


ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 installer.py rollback"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Rollback failed; preserve the error' }
  • Expect rolled_back: true and the backup identifier. Query status again with section 1.
  • After rollback to a pre-integration state, managed: false and ace_version: null can be normal.
  • Files changed by hand after installation cause a refusal, to protect later edits. Do not delete them blindly.

7. Host recovery when Klipper cannot become ready

This does not recover ACE firmware or bypass active printing or an unresolved ACE transaction.

Use only when the original installer has finished, movement has stopped, drying and heating are off, and actual temperatures are below 50 °C.

If the screen or independent observation cannot confirm cooling and no movement, stop. An unreadable network state is not evidence of idle hardware.

If section 1 reaches SSH but normal status cannot become ready, this command skips the initial online-ready check.

It keeps the firmware, backup, file-hash, ACE-transaction, and post-restoration ready checks:


ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 installer.py rollback --offline-recovery --confirm-idle-and-cold"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Recovery failed; preserve the error' }

For No managed installation; offline recovery requires an explicit backup ID, use only the exact Backup ID from the window or log of this failed operation:


$BackupId = (Read-Host 'Enter the backup identifier from this failed installation').Trim()
if ($BackupId -notmatch '^[0-9]{8}T[0-9]{12}Z$') { throw 'STOP: Invalid backup identifier' }
ssh.exe $PrinterTarget "cd '$RemoteDir' && python3 installer.py rollback --backup '$BackupId' --offline-recovery --confirm-idle-and-cold"
if ($LASTEXITCODE -ne 0) { throw 'STOP: Recovery failed; do not try another backup at random' }

Expect rolled_back: true. If restoration still fails, stop and keep the error. Do not try other backup identifiers at random.

This page cannot guarantee automatic recovery from every firmware, file, or hardware fault.

U1 firmware updates are separate

Save private configuration and backups first. Confirm that this project supports the target firmware.

Follow U1 preparation. After the reboot, check Wi-Fi, Advanced Mode, and Root Access.

Reinstall only if this project's check accepts the target. Host-file restoration cannot roll back U1 or ACE firmware.
