# 故障排查

[English](troubleshooting.md) · [安装向导](quick-start.zh-CN.md) · [日常使用](daily-use.zh-CN.md)

不确定耗材停在哪里时，不要重复点进料或退料。
保持机器空闲，保存完整报错。

> [!IMPORTANT]
> **哪一步出了问题，就用哪一步的恢复方法。**
> **不要因为电脑断线就重新刷一次固件。**

| 问题发生在哪一步 | 先做什么 |
| --- | --- |
| U1 屏幕上的固件更新 | 保存屏幕报错，按 [U1 固件恢复说明](u1-preparation.zh-CN.md)处理。 |
| ACE 固件更新，或不知道更新结果 | 保持电源和 USB 连接。打开同一版本的安装包，选菜单 **4**，查看保存的结果。见 [ACE 恢复说明](ace-wizard.zh-CN.md)。 |
| U1 主机适配安装 | 查看安装成功或恢复的结果。重新安装前先看[主机恢复说明](update-and-rollback.zh-CN.md#after-an-interrupted-installation)。 |
| 安装后日常进料、退料或 NFC 不正常 | 按下面检查，不要先去重新刷固件。 |

`Automatic rollback VERIFIED` 只涉及主机文件和服务，不表示 ACE 或 U1 固件已回退。

## 连接和安装

| 看到什么 | 检查什么 | 下一步 |
| --- | --- | --- |
| SSH 拒绝连接 | Root Access、U1 当前 IP、电脑网络 | 按[连接步骤](installation.zh-CN.md#confirm-the-connection)核对。电脑和 U1 要在同一局域网。 |
| 输入密码时没有字母或星号 | SSH 本来如此 | 输入 root SSH 密码后按回车。这不是 Wi-Fi 密码。 |
| Windows 找不到 `ssh` 或 `scp` | 缺少 OpenSSH 客户端 | 按[快速开始](quick-start.zh-CN.md)里的 Windows 组件步骤安装。 |
| 更新 U1 固件后找不到机器 | 屏幕上 Wi-Fi 是否连接、IP 是否变了 | 重新连接 Wi-Fi，使用现在的 IP。 |
| 打不开 `/firmware-config/` | Advanced Mode、当前 IP | 在 U1 上开启 Advanced Mode，并按要求重启。 |
| 找不到 ACE，或出现多个串口候选 | ACE 电源、第一代硬件、经过确认的连接线 | 只接一台 ACE。断电检查硬件后，再做只读检查。不要猜测或修改串口路径。 |
| 安装器拒绝某个核心文件 | 文件被手动改过，或软件版本不支持 | 保留文件和报错，用于兼容迁移。不要删除或覆盖文件来绕过检查。 |
| 安装器拒绝固件版本 | 是否为指定的兼容基线 | 保留现有固件，对照 [U1 固件准备](u1-preparation.zh-CN.md)核对显示的版本。不要强行通过检查。 |
| 安装器拒绝现有配置 | 重复或异常的 ACE 配置段 | 保存并核对显示的配置路径，再决定修改。不要删除其他配置。 |
| 重启后改动消失 | 持久化、最近的固件更新 | 重新安装前先读取[安装状态](update-and-rollback.zh-CN.md#read-installation-status)。 |
| Klipper 显示未连接 | `klippy.log` 里的启动错误 | 先解决这个错误，再测试进退料。 |

Klipper 未连接时摄像头可能仍然能用。有画面不代表耗材控制已就绪。

## 进料和退料

| 看到什么 | 含义或检查方向 | 下一步 |
| --- | --- | --- |
| 插入耗材后只咬一小段就停 | 预期行为 | 需要完整进料时，在 U1 上对该槽点进料。 |
| NFC 识别期间进料在等待 | 识别有单独的就绪等待。 | 等待，不要反复点进料。 |
| 第二个槽在等待 | 同一时间只有一个操作占用 ACE 输送。 | 等正在执行的操作结束。 |
| 重启后进料较慢 | 起点未知，所以使用由传感器控制的慢速进料。 | 让它完成。卡料或报错时停止，不要强行开启快段。 |
| 回送消松后，下次快段变短 | 软件会从快送距离 B 中扣除已回送的距离。 | 按自己的 B、C 值核对。仅为示例：1150 减 300 得 850 mm。 |
| 进料出现行程或超时错误 | 打印头传感器没有确认到料。 | 先检查管路和打印头传感器。不要重复长送。 |
| 退料后仍有松圈 | 新安装默认关闭回送消松；已有的回送距离也可能不够。 | 先确认正常进料和退料，再按[回送消松校准](configuration.zh-CN.md#enable-forward-take-up)设置。 |
| 退料报错后没有回送消松 | 没有确认回抽正常完成。 | 先处理退料错误。 |
| 退料后耗材仍在后方 PTFE 管里 | 这是设计：保留耗材供下次进料。 | 核对 ACE 入口有料、打印头无料。 |
| 收到停止响应后仍短暂动作 | ACE 某些换挡状态不能立即停住。 | 普通进退料操作中动作变得不安全时，关闭 ACE 的电源开关。 |

回送消松是把耗材送入后方 PTFE 管，消耗外面的松圈。
它不检测张力，不单独控制滚筒转动，也不会把松散的耗材卷回料盘。
主机没有独立的滚筒调速参数。示例回送距离不适用于所有管路。

## NFC 和材料显示

| 看到什么 | 检查什么 | 下一步 |
| --- | --- | --- |
| 类型和颜色正常，但品牌是 Generic | 显示是否已刷新 | 重新打开 U1 上该槽的详情。仍为 Generic 时，核对准确的 ACE 构建和标签支持表。保持选择 External。 |
| U1 显示 Bambu，切片软件里没有 | 切片软件自己的品牌和材料预设 | 分别核对切片预设和 U1 槽位详情。不要因此改 ACE 固件。 |
| ACE 没有识别标签 | ACE 固件、标签格式、是否有原装标签、标签位置 | 对照 [NFC 支持表](nfc.zh-CN.md)。无标签或不支持的料卷可以手填材料。 |
| U1 的 OpenRFID 能读，ACE 不能 | 两者的读卡器和解码程序不同 | 检查 ACE 这条路径。不要复制 U1 的密钥。 |
| 真正拔出 ACE 入口后材料消失 | 预期的清除事件 | 重新插入，等待新的识别。 |
| 只从打印头退料后材料消失 | 材料保留模块可能缺失。 | 核对本项目的安装版本和状态。 |
| 后台没有耗材卡片 | Klipper 状态、网页布局、可用组件 | 先恢复 Klipper 就绪，再比较界面。 |

ACE 材料路径使用 **External** 模式。改回内置 OpenRFID 不会升级 ACE 的读卡能力。
修改检测设置前，先看 [NFC 说明](nfc.zh-CN.md)。
指定 OpenCubic 固件支持的标签，不需要你提供 NFC 密钥。

## 只读查看状态，不触发运动

**主机安装状态：** 按[读取安装状态](update-and-rollback.zh-CN.md#read-installation-status)操作。它会确认打印机上正确的暂存目录。不要假设以前的 PowerShell 窗口里变量仍然正确。连接基础见[确认连接](installation.zh-CN.md#confirm-the-connection)。

**ACE 状态（可选）：** 下面的步骤读取 U1 网页已有的数据。
不发送运动命令，也不另开 ACE 串口连接。
只在主机适配安装完成后使用。ACE 固件更新结果未明确时，改用菜单 **4**。

1. 按 **Windows 键 + R**，输入 `powershell`，按回车。
2. 把下面这一行复制到窗口，按回车。
3. 出现提示后，输入 U1 Wi-Fi 屏幕上当前的 IP。不要加 `http://` 或路径。按回车。

```powershell
$PrinterAddress = (Read-Host "Current printer IP from the Wi-Fi screen").Trim()
```

4. 再把下面这一段复制到窗口，按回车。

```powershell
$AceStatus = Invoke-RestMethod "http://$PrinterAddress/printer/objects/query?ace"
$AceStatus.result.status.ace | Format-List
```

没有结果或返回错误时，检查 Klipper 是否就绪，并保存报错原文。
不要为了让查询通过而修改运动参数。

| 字段 | 含义 |
| --- | --- |
| `connected`、`status_fresh` | ACE 是否连接、状态是否最新。正常运行时两项都应为 True。 |
| `status`、`last_error` | 当前 ACE 状态和最近一次报告的错误。 |
| `gate_status` | 第 1 到第 4 槽的入口状态：`0` 无料、`1` 有料、`-1` 未知。未知不等于无料。 |
| `fast_origins`、`fast_origin_advance_mm` | 已知的进料起点，以及退料后已经向前送过的距离。 |
| `rfid_sync` | 各槽材料信息的同步进度。 |

## 准备问题报告

1. U1 固件的完整版本。
2. ACE 的代际、运行版本和已知的固件来源。
3. 本项目的安装版本。
4. 出问题的槽号。
5. 最后一次成功的动作。
6. 分别描述耗材和料盘或滚筒的动作：是否移动、何时停止。
7. 报错原文，以及经过检查和脱敏的必要日志片段。

不要上传私人 NFC 密钥、完整配置备份、密码或未经检查的设备数据。
可复现的主机适配问题，请在[项目问题页面](https://github.com/Alexantry/Ultimate-U1-ACE-link/issues)报告。
