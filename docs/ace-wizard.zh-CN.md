# ACE 固件：跟着双语向导完成

[English](ace-wizard.md) · [新手入口](quick-start.zh-CN.md) · [中文手动安装](installation.zh-CN.md) · [手动刷机参考（英文）](ace-firmware.md)

Windows 安装向导现在包含 ACE 固件准备阶段。
你不需要输入命令、编辑设备配置或在电脑安装 Python。
维护工具通过 SSH，在已完成前置准备的 U1 上运行。
ACE 的[这些 NFC 格式支持](nfc.zh-CN.md)由 OpenCubic 提供；使用支持的标签时，不需要自行寻找或填写 NFC 密钥。

> [!IMPORTANT]
> **只适用于 ACE Pro 第一代，不适用于 ACE 2 Pro。**
> **U1 必须先安装指定扩展固件，开启 Advanced Mode，并将 Root Access 设为 Open。**
> **遇到未验证的 ACE 源版本，向导会停止，不会强行刷写。**

## 安装包里有什么？

包内只有可阅读的维护程序和双语提示，**没有固件二进制、NFC 密钥或私人设备配置**。
你选择准备固件后，程序才从指定上游下载准确的文件。
下载由 U1 执行，因此 U1 必须能够联网访问 GitHub；电脑保持与 U1 在同一局域网。
下载后检查大小、SHA-256 和固件格式；检查通过前不能开始写入。

## 哪些版本可以直接跟向导更新？

| 实际检测结果 | 向导的处理 |
| --- | --- |
| 第一代，应用版本 `V1.3.856`，引导程序 `V1.0.1` | 通过全部检查后，可以更新到指定目标。 |
| 已显示 `CV1.3.863` | 不重复刷写；询问你是否已安装指定 OpenCubic 版本，且 NFC 正常。 |
| 其他源版本、引导版本、代际或无法确认身份 | 停止；不猜测、不修改检测结果、不强行启用写入。 |

目标固件的运行版本显示为 `CV1.3.863`。
这个字符串不能区分所有社区修改版。
不知道之前刷了什么时，不要把“已有正确版本”的问题回答为已确认。

向导也可以用本次重新探测结果，匹配过去 24 小时内由本向导完成的成功记录。
ACE 身份、设备信息和目标镜像哈希都必须匹配；旧成功记录本身不能证明当前连接的 ACE 已通过检查。

## 开始前

1. 等打印、进料、退料及其他耗材动作结束。
2. 第一次安装本项目时，先用正常退料退出四个 U1 打印头，再退出四个 ACE 入口的耗材。
3. 关闭加热和烘干。退料可能加热喷嘴，结束后等待打印机所有加热器降到 50℃ 以下。
4. 连接硬件前关闭两台设备。接好已核对的第一代 ACE USB 连接线及四路料管后，再开机。
5. 必要时完成 [U1 固件准备](u1-preparation.zh-CN.md)，确认 Advanced Mode 开启、Root Access 为 Open。
6. 开始维护后，保持 ACE 电源和 USB 连接稳定。
7. 维护及重启期间，手离开滚筒。

已有本项目、只是更新时，不要求清空入口；仍需空闲并冷却，关闭加热和烘干。

程序会核对空闲状态、加热目标、温度、烘干和串口占用。
它不会发送进退料命令来让失败检查通过。
设备或服务初始化仍可能触发 ACE 自身动作；请保持手离开滚筒。
如果仍有动作，先用设备正常控制结束，再重新准备。

## 跟窗口操作

1. 完整解压项目压缩包。
2. 双击 **START-HERE.cmd**，选择中文或 English。
3. 按下表选择任务。
4. 按提示输入当前打印机 IP 和 SSH root 密码；填写方法见[主安装指南](quick-start.zh-CN.md#4-填写连接信息)。
5. 如果存在上次 ACE 更新记录，先查看结果，再考虑新的维护。
6. 阅读并确认准备条件。
7. 等待下载、校验及实际设备检查完成。
8. 核对显示的源版本、引导版本和目标版本，并确认设备是 ACE Pro 第一代。
9. 只有显示的组合正确时，才确认一次固件更新。
10. 保持供电，等待完整验证结果。

| 你的任务 | 主菜单怎么选 | ACE 完成之后 |
| --- | --- | --- |
| U1 已准备好，要安装本项目 | **1. U1 已准备好** | 在同一窗口继续主机适配安装。 |
| 先准备 U1，再安装本项目 | **2. 准备 U1 固件 U 盘** | 完成 U1 屏幕步骤，再继续 ACE 与主机适配安装。 |
| 只维护 ACE，或查询上次 ACE 结果 | **4. ACE 固件** | 完成 ACE 维护；如还要安装主机适配，重新打开向导，选菜单 1。 |

菜单 1、2 不要求你先完成另一套手动 ACE 刷机流程。
菜单 3 打开所选语言的手动文档，然后退出。

准备阶段会暂时停止 Klipper，以便独占 ACE 接口。
完成仅检查、不刷写的过程后，会恢复并核对打印机后台就绪。
真正开始更新后，事务在 U1 上独立运行并记录状态，即使电脑 SSH 断开也可以继续。

> [!CAUTION]
> **电脑不再显示进度，不代表要重新刷一次。**
> **写入期间不要切断 ACE 电源。**
> 使用**同一版本的安装包**重新打开向导，选择菜单 **4** 查看上次更新结果。
> 已有事务时，这个入口先读取保存的结果，不会自动重复写入。

## 怎样才算成功？

执行固件写入后，程序必须观察到运行版本变为目标值，并连续收到就绪状态。
然后恢复 Klipper，核对 U1 配置、传感器及材料信息的保留情况。
已开始更新的操作，只有得到完整成功结果，才允许继续主机安装。
如果原来已装好准确固件，则通过“已确认正确版本”的路径继续，不需要重复写入。

新 NFC 解码可能让非空品牌、材质或颜色发生变化，例如 Generic 变成 Bambu。
向导会显示变化，要求你对照当前料盘核对，再进入主机适配安装。
它不会把新品牌自动改回 Generic；原有材料信息丢失也不会被当作保留检查通过。

这不是固件全量回读，也不是对 ACE 内部全部校准值的验证。
它也不能证明每一种 NFC 标签都可读取。
适配安装完成后，请对四槽逐一做受控的[进料 → 退料 → 再进料](daily-use.zh-CN.md)，一次只测一槽，并对照料盘核对品牌、材质和颜色。
原有管长参数应保留；更新固件不能替你测量新管路。
第一次安装在安装前审查初始长度，安装后用上述四槽测试验证。

## 停止或断线后怎么办？

| 提示或情况 | 你该做什么 |
| --- | --- |
| 下载或校验失败 | 检查网络；失败文件不会进入刷写步骤。 |
| 机器正在加热、烘干、打印或使用 ACE | 正常结束对应动作，等待满足条件后再准备。 |
| ACE 版本或设备不受支持 | 保留原固件，保存显示的版本供兼容性核对。 |
| 已显示 `CV1.3.863`，但不知道固件来源 | 不把它确认成指定版本，保持固件不变。 |
| 上次更新仍在运行 | 保持供电，继续查询同一事务。 |
| 电脑断线 | 使用同一版本安装包重开向导查看上次结果，不重复刷写。 |
| 已开始更新，但结果无法确认 | 保持打印控制停止，保留私人记录，按显示的恢复信息处理。 |

发送过部分数据不等于升级成功。
程序不会自动刷原厂包、清空事务或恢复打印。
如果后台任务在**尚未尝试写入固件之前**停止，菜单 **4** 可以提供“仅检查并恢复”的操作。
确认一次后等待检查 ACE 并恢复服务；该操作不刷固件。只要曾经尝试写入，就不会提供此恢复操作。
超出已验证路径的故障仍可能需要[手动维护和恢复（英文）](ace-firmware.md#uncertain-results-and-recovery)。
不要修改记录文件来绕过拒绝条件。

**ACE 固件成功不等于主机适配已安装成功。**
后面的主机安装失败时，使用[主机更新和回退说明](update-and-rollback.zh-CN.md)。
`Automatic rollback VERIFIED` 只表示主机文件和服务已回退，不表示 ACE 固件已恢复。

私人事务记录留在打印机的 `/userdata/ultimate-u1-ace-link/ace-firmware/` 目录下。
尚有未处理的固件事务时，新版主机安装和回滚都会停止；不要同时运行旧安装器或独立的手动维护工具。
不要公开设备身份、密码、NFC 密钥或未脱敏的维护日志。

## 验证范围

原始传输路线已在上表中的源版本和引导版本上实测。
新增向导和事务调度使用模拟设备、服务、下载及故障进行测试，尚未独立完成从头到尾的实机安装验收。
原有四个送料、退料及 NFC 核心模块保持不变。
